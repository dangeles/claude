# Evidence

Goal: for each section, know what it claims and what those claims rest on — before writing
prose that assumes an argument you haven't checked.

Work section by section, but don't be rigid about it. If the user wants to draft a section
whose evidence is already solid, go draft it.

## For the section at hand

Work out, in conversation:

- What does this section actually claim?
- What does each claim rest on — a study, a number, a mechanism, an analogy, reasoning?
- Does the order build, or does point 3 assume point 5?
- What does a reader who disagrees say here?

Propose two or three ways the section could run and let the user pick. Proposing options
beats proposing one answer; it surfaces what they actually think.

## Play devil's advocate

This is where the essay gets strong or stays soft. Take the opposing position seriously and
argue it:

- The best version of the counterargument, not a strawman.
- Where the evidence is thinner than the claim.
- Where correlation is being asked to carry causation.
- What a domain expert would object to.
- Which of the user's claims is load-bearing — if this one falls, does the essay?

The load-bearing claims are the ones worth checking. A colorful detail that's wrong is
embarrassing; a load-bearing claim that's wrong means the essay is wrong.

## Checking claims

Batch a section's factual claims into one fact-checker invocation rather than checking them
one at a time. See `fact-checking.md` for what to check and what to skip.

When something doesn't verify: revise the claim to match what's actually known, hedge it
honestly in the text, or cut it. Saying "estimates vary between X and Y" is usually better
writing than a false precision. If the user wants to keep a claim you couldn't confirm,
that's their call — say once that it's unverified, then let it go.

## Done when

Each section has claims, support, and an answer to its strongest objection. Keep this as
brief notes under each section heading in the draft file — a few lines, not a formal
argument map. It exists to write from, then it gets deleted.
